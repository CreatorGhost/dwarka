The finalized choice

PlayCanvas Free is the better hackathon tool. React Three Fiber remains the runner-up.

PlayCanvas Free with a server-authoritative JavaScript runtime

The visual Editor is the deciding advantage. It gives the team faster scene assembly, animation graphs, particles, lighting, physics components, and an official third-person starting point. The exported browser build connects to the existing server over WebSocket and can be embedded in the React site.

Requirements by framework

These are the practical setup obligations, not marketing feature lists.

PlayCanvas: finalized path
  • Create one free public Editor project. Keep credentials, private notes, and server secrets out of it.
  • Start from the official third-person project, then tune WASD, mouse look, shoulder aim, camera collision, dodge, bow, and blade controls.
  • Build locomotion and combat with PlayCanvas animation state graphs. Assemble arenas, lights, collisions, particles, and spawn points in the Editor.
  • Use plain JavaScript WebSocket messages for sequenced player input and authoritative server snapshots.
  • Download the static build, self-host it on the existing server, and embed it beside the React site. Do not use the 0.x React renderer.
React Three Fiber: runner-up
  • Upgrade React, React DOM, and React Server DOM together from 19.2.6 to 19.2.8 before installing ecctrl 2.0.1.
  • Add Three, R3F, drei, react-three-rapier, ecctrl, particles, post-processing, and game-specific state systems.
  • Create a client-only game route and build scene placement, animation transitions, combat, VFX tuning, and debugging tools in code.
  • Use this only if keeping every system in the existing React repository matters more than the 72-hour visual-production advantage.
Independent Fable review
  • Fable chose PlayCanvas Free with a public Editor project.
  • Its deciding reasons were the official third-person starting point, visual scene assembly, editable animation graphs, particle tools, and isolation from the existing vinext runtime.
  • It judged R3F's dependency alignment, code-built scenes, custom animation transitions, and VFX tuning to be the larger delivery risk.
My technical review
  • I also choose PlayCanvas. The game is judged on how complete and convincing it feels, not on whether every scene object was authored as a React component.
  • R3F has cleaner site integration and shared TypeScript, but those benefits do not recover the time spent building visual game tooling.
  • The public-project condition is acceptable for this personal hackathon because the game uses free public assets and contains no client-side secrets.
  • This is a final commitment, not a four-hour framework experiment. Cut features if needed rather than switching engines mid-build.

Server-authoritative, browser-rendered

The laptop renders the 3D world locally while your existing server owns the rules and results.

Browser at 60 fps

Samples input, predicts movement, renders 3D, blends animation, plays VFX and audio, and draws the HUD.

→
WebSocket input stream

Sends sequenced movement, aim, dodge, attack, mercy, and astra inputs. It never sends a claimed hit or damage value.

→
Server at 20 Hz

Validates movement and owns AI, collisions, hits, health, i-frames, boss phases, checkpoints, mercy, and win or fail.

What stays simple: server collision uses arena bounds and simple capsule, circle, or box tests. Do not build a second full navmesh or a second detailed physics world.

How it becomes a proper 3D game

The visual target is stylized real-time 3D, not photorealism and not a flat website effect.

The visual recipe

  • Characters: skinned 3D meshes with blended locomotion, bow, melee, dodge, hit, and death clips
  • Camera: third-person spring camera with shoulder aim and collision avoidance
  • World: three distinct arenas with real geometry, fog, lighting, shadows, water, and instanced props
  • Combat: real projectiles, hit volumes, trails, sparks, elemental VFX, and readable telegraphs
  • Story: the existing 32 illustrated panels hide loading and preserve the complete journey

The browser budget

  • PC laptop target at 1080p with keyboard and mouse
  • WebGL2 launch baseline, no required WebGPU
  • 30k to 60k visible triangles near the player
  • One 1K or 2K atlas per asset family
  • Instanced trees, rocks, and arena props
  • One shadowed directional light
  • Meshopt geometry and compressed textures
  • 45 fps minimum, 60 fps target on the agreed laptop

The 72-hour PlayCanvas delivery path

The engine decision is closed. Each block should produce something that can be judged immediately.

Hours 0 to 6

Prove the player

Clone the official third-person project. Import one free character and deliver WASD, mouse camera, shoulder aim, dodge, bow, blade, and one reliable hit.

Hours 6 to 18

Prove authority

Connect the WebSocket. Let the server validate movement and own one enemy, hit resolution, health, i-frames, death, and restart.

Hours 18 to 42

Build the vertical slice

Finish one arena with chariot wheel damage, enemy telegraphs, elemental VFX, sound, mercy choice, and a complete win or fail loop.

Hours 42 to 72

Polish and package

Add only encounters that reuse proven systems. Profile the 1080p laptop build, compress assets, export static files, embed the game, and rehearse the judge flow.
